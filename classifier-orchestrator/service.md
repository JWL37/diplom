Цель разработки заключается в снижении трудоёмкости модерации пользовательских комментариев за счёт создания платформы, которая автоматизирует переобучение модели классификации. Для достижения этой цели разрабатываемое решение должно обеспечивать управление целевыми классами через веб-интерфейс, подготовку и разметку данных для последующего переобучения, запуск обучения новой версии модели, хранение результатов обучения и развёртывание актуальной версии модели в рабочей среде.
2.2 Функциональные требования
Разрабатываемая платформа должна обеспечивать выполнение набора функций, связанных с подготовкой данных, переобучением модели классификации комментариев и вводом новой версии модели в эксплуатацию.
К основным функциональным требованиям относятся следующие:
управление классами классификации:
 – добавление новых классов;
 – просмотр перечня классов;
 – изменение наименований классов.
разметка данных:
 – загрузка комментариев для разметки;
 – присвоение комментариям целевых классов;
 – сохранение результатов разметки.
переобучение модели:
 – запуск переобучения на основе размеченных данных;
 – сохранение новой версии модели после завершения обучения.
развертывание модели:
 – выбор обученной версии модели;
 – ввод выбранной версии в эксплуатацию.
предоставление программного интерфейса:
 – приём текста комментария для классификации;
 – возврат результата классификации.
Функциональные требования определяют минимально необходимый состав возможностей платформы, достаточный для перехода от ручного переобучения модели к более упорядоченному и воспроизводимому процессу обновления системы классификации комментариев.
2.3 Программное обеспечение
В рамках разработки платформы используется набор технологий, обеспечивающих реализацию серверной части, обработку моделей машинного обучения, хранение данных и взаимодействие между компонентами системы.
Для реализации серверных микросервисов выбран язык программирования Go. Его применение позволяет создавать производительные и устойчивые к нагрузке сервисы с простыми механизмами параллельного выполнения. Кроме того, Go широко применяется при разработке сетевых приложений, что упрощает создание сервисов с большим числом одновременных запросов и снижает затраты на сопровождение.
Для разработки компонента, связанного с обучением и переобучением модели классификации, используется язык Python. Такой выбор обусловлен наличием большого числа библиотек для машинного обучения и обработки текстов. Python позволяет быстро реализовать и протестировать модель, а также упростить дальнейшее развитие алгоритмов без изменения общей архитектуры системы.
В качестве хранилища файлов используется MinIO. Он применяется для сохранения весов моделей и их версий. Выбор MinIO обусловлен поддержкой объектного хранения и совместимостью с распространёнными интерфейсами работы с хранилищами, что упрощает организацию хранения и доступа к результатам обучения.
Для хранения структурированных данных применяется система управления базами данных PostgreSQL. Она используется для хранения информации о классах классификации, пользователях и других сущностях платформы. PostgreSQL обеспечивает надёжность хранения данных, поддержку сложных запросов и возможность масштабирования при увеличении объёма информации.
Для организации асинхронного взаимодействия между сервисами используется Kafka. Применение брокера сообщений позволяет разделить процессы в системе и снизить связанность компонентов. Это упрощает обработку длительных операций, таких как обучение модели, и повышает устойчивость системы при пиковых нагрузках.
Для синхронного взаимодействия между сервисами применяется gRPC. Использование этого протокола позволяет снизить задержки при обмене данными между компонентами системы и обеспечить строгую типизацию передаваемых сообщений. Это особенно важно при взаимодействии между сервисами, реализованными на разных языках программирования.
Для взаимодействия с пользовательским интерфейсом используется REST-подход. Он обеспечивает простое и понятное взаимодействие между клиентской частью и сервером, что упрощает разработку веб-интерфейса и его дальнейшее сопровождение.
Выбранный набор технологий ориентирован на построение распределённой системы, в которой отдельные компоненты могут развиваться независимо друг от друга. Используемые решения широко распространены в промышленной разработке, что упрощает поиск специалистов для поддержки и развития проекта. Кроме того, такой стек технологий остаётся актуальным и позволяет в дальнейшем расширять функциональность системы без существенной переработки архитектуры.
Веб-приложение используется в качестве пользовательского интерфейса системы. С его помощью выполняются:
управление классами комментариев;


 работа с голденами;
запуск процессов переобучения;
развёртывание новой версии модели.
Взаимодействие с серверной частью осуществляется по протоколу HTTP. Веб-приложение не содержит логики обработки данных и используется для передачи запросов в сервис координации. Сервис координации классификации является центральным элементом системы. Он обеспечивает:
прием запросов от веб-приложения и внешних систем;
взаимодействие с базой данных;
управление процессами переобучения;
передачу запросов в сервис классификации;
обмен сообщениями через брокер.
Таким образом, данный компонент реализует основную бизнес-логику системы и обеспечивает согласованную работу остальных модулей.
Сервис классификации предназначен для определения класса пользовательского комментария. Классификация выполняется с использованием метода ближайших соседей. Для каждого комментария формируется векторное представление, после чего определяется ближайшее множество эталонных примеров. На основании этого выбирается соответствующий класс.Сервис выполняет следующие функции:
загрузку актуальной версии модели из хранилища;
обновление индекса при переобучении;
обработку запросов на классификацию.
Выделение данного компонента в отдельный модуль позволяет независимо изменять алгоритмы и масштабировать вычислительную нагрузку. База данных предназначена для хранения структурированной информации, включающей:
перечень классов;
голдены (эталонные примеры);
метаданные версий моделей;
