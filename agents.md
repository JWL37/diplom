# Инструкции для агентов

Этот файл описывает ожидаемый функционал системы и роли сервисов. Он нужен, чтобы следующие агенты могли разрабатывать код согласованно и в рамках архитектуры.

## Контекст системы
- Веб-приложение общается с сервисом координации (Go, REST).
- Сервис координации управляет бизнес-логикой и хранит состояние в PostgreSQL.
- Сервис классификации (Python) выполняет ML-инференс и переобучение.
- Асинхронные задачи переобучения идут через Kafka.
- Артефакты моделей хранятся в MinIO (S3).
- Синхронное взаимодействие между сервисами через gRPC.

## Роли сервисов

### Сервис координации (classifier-orchestrator, Go)
Смысл: центр бизнес-логики и контроль жизненного цикла моделей.

Функции:
- Управление классами:
  - добавление новых классов;
  - просмотр перечня классов;
  - изменение наименований классов;
  - добавление и удаление голденов;
  - поиск по голдену.
- Разметка данных:
  - загрузка выборок комментариев;
  - отбор и сохранение утвержденных комментариев как голденов.
- Переобучение:
  - формирование задачи на переобучение и отправка в Kafka;
  - фиксация статуса обучения в БД.
- Развертывание модели:
  - выбор обученной версии модели;
  - откат к предыдущей версии.
- API для внешних систем и фронта:
  - REST интерфейс для управления классами, голденами, обучением, развертыванием.
- gRPC клиент для вызова сервиса классификации:
  - Classify (инференс);
  - ReloadModel (развертывание конкретной версии).

### Сервис классификации (classifier, Python)
Смысл: ML-ядро, отвечает за построение и использование модели.

Функции:
- Инференс:
  - прием текста и возврат результата классификации;
  - поиск ближайших соседей в FAISS-индексе;
  - расчет уверенности.
- Переобучение:
  - получение задачи из Kafka;
  - загрузка голденов для версии;
  - пересчет эмбеддингов и построение нового FAISS-индекса;
  - сохранение артефактов версии в S3.
- Уведомление о готовности:
  - отправка результата обучения в Kafka.
- Развертывание:
  - gRPC метод ReloadModel для загрузки выбранной версии в память без рестарта.

## Жизненный цикл модели

### Переобучение
1. Пользователь инициирует обучение через фронт.
2. Оркестратор отправляет задачу в Kafka.
3. Python сервис обучает модель, сохраняет артефакты в S3.
4. Python сервис отправляет событие о готовности в Kafka.
5. Оркестратор обновляет статус версии в БД.

### Развертывание и откат
1. Пользователь выбирает версию или откат через фронт.
2. Оркестратор вызывает gRPC ReloadModel в Python сервисе.
3. Python сервис загружает артефакты из S3 и обновляет модель в памяти.
4. Оркестратор фиксирует активную версию в БД.

## Что нужно реализовать (весь функционал приложения)

### Управление классами
- CRUD для классов предсказаний.
- Поиск по голдену.

### Управление голденами
- Загрузка выборки комментариев.
- Подтверждение и сохранение эталонных примеров.
- Привязка голденов к классам.

### Переобучение
- Формирование задач на обучение через Kafka.
- Хранение статусов задач и версий.
- Сохранение артефактов версии в S3.

### Развертывание
- Выбор активной версии модели.
- Откат к предыдущей версии.
- Горячая подмена модели в Python сервисе через gRPC.

### Классификация
- gRPC метод Classify (сервис Python).
- REST-эндпоинт в оркестраторе, проксирующий запросы классификации.

## Технические требования
- Go: slog для логирования, chi для роутинга, контекст в каждом методе.
- Интерфейсы размещать в месте использования.
- Код писать в стиле Go, без комментариев в коде.
- Python: gRPC сервер + Kafka consumer + S3 client + FAISS.
